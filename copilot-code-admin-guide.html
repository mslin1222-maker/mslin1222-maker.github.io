Copilot Code 啟用與管理指南

本指南說明 Copilot Code 的功能定位、啟用條件、設定步驟、管理控制項與 Copilot Credits 費用控管，協助 IT 管理者規劃導入。內容依據 Microsoft Learn 官方文件整理。

官方文件：https://learn.microsoft.com/en-us/copilot/code/

免責聲明Copilot Code 目前為 Frontier 預覽功能，相關資訊更新快速，功能、預設值、設定名稱與計費方式可能隨時異動。本指南內容以 2026/10/22 為準，請隨時關注 Microsoft Learn 官方文件的最新內容，並以租戶實際畫面為準。

!重點摘要（Executive Summary）

  1. 啟用條件：使用者須同時符合三項條件，方可使用 Microsoft Copilot app 中的 Code（程式碼）分頁：① 具備 Microsoft Copilot 授權；② 納入 Frontier；③ 於 spending policy 勾選 Code 與 Copilot Managed Runtime。
  2. 使用費用：Copilot Code 以 Copilot Credits 計費，與 Copilot Cowork 適用相同的 spending policy。spending policy 中的「Allow new Agents and services as they become available」預設為開啟，新服務推出後將自動納入既有政策；若未調整，Code 與 Cowork 將共用同一額度。
  3. 無需 GitHub 授權：僅需 Microsoft Entra 工作帳號。GitHub 連線為選用功能，預設為關閉。
  4. 建議作法：選定試行人員，並設定 spending policy（關閉自動納入新服務，勾選 Code 與 Copilot Managed Runtime）→ 設定每人上限與警示 → 小範圍試行 → 依 Consumption 報表評估後逐步擴大。

1功能概述

Copilot Code 讓非開發人員以自然語言建置可實際運作的工具。

Copilot Code 是 Microsoft Copilot app 中的 Code 分頁。使用者描述所需成果（例如儀表板、內部工具、靜態網站、資料轉換或 script），Copilot Code 即進行建置，於畫布（canvas）即時預覽，並依回饋反覆調整，全程無須具備程式開發能力。

適用產出

儀表板、追蹤表、表單、計算器、內部工具、自動化流程、script、靜態網站。

執行位置

Local：使用者裝置上的專案資料夾。
Cloud：Microsoft 雲端隔離環境，支援跨裝置存取與組織內分享。

支援平台

Windows（x64 / Arm）、Mac（Intel / Apple silicon）桌面 app；網頁版支援雲端開發。目前版本未提供行動版。

產品定位

Cowork 著重研究、分析與文件撰寫；Code 著重軟體產出；Copilot Studio 用於企業級 agent；GitHub Copilot 適用專業開發流程。

管理面定位Copilot Code 於組織既有的 Microsoft 365 環境內運作，沿用既有的身分、合規與稽核治理機制。雲端 app 須由使用者另行發佈至 Copilot Managed Runtime 後才能分享，建置完成後不會自動發佈。

2啟用條件

下列三項條件均須成立，使用者方可看到並使用 Code 分頁。

① Copilot 授權使用者已指派 Microsoft Copilot 授權
→
② Frontier 存取租戶已加入 Frontier，且使用者位於允許範圍內
→
③ Spending policy 勾選 Code 與 Copilot Managed Runtime允許政策內使用者以 Copilot Credits 使用 Code

組織層級設定說明

「組織層級設定」係指管理者於 Microsoft 365 admin center 針對整個租戶所做的設定，與使用者授權為兩項獨立條件。Frontier 階段主要涉及以下兩處：

  1. Copilot › Settings › View all › Copilot Frontier：設定可看到 Code 分頁的使用者範圍。
  2. Copilot › Cost management › Spending policy › Agents and services：設定可使用 Code 的使用者範圍。政策中須勾選 Code 與 Copilot Managed Runtime（設定方式詳見 STEP 1）。

Automatic approval in Code、Code execution location、GitHub account connection in Code、Organization data in local Code sessions 等其他控制項，詳見第 4 節，均套用於整個租戶。

狀態判讀使用者可看到「程式碼」分頁，但畫面顯示「要求存取權（Request access）」時，表示 Frontier 已開放，但使用者尚未納入含 Code 的 spending policy，或政策變更尚未生效。

啟用前檢查清單（Pre-flight checklist）

  • 授權：目標使用者已指派 Microsoft Copilot 授權。Copilot Code 無獨立 SKU，使用量以 Copilot Credits 計算。
  • Frontier：於 Copilot › Settings › View all › Copilot Frontier 指定可使用 Frontier 功能的使用者或群組（預設不開放任何使用者）。
  • 計費：已於 Cost management 啟用 usage-based billing，並完成 billing method 設定（P3 預購、Pay-as-you-go 或預付容量）。
  • 管理角色：建立 spending policy 須具備 Global Administrator 或 Billing Administrator 角色；AI Administrator 與 License Administrator 可編輯但無法建立政策；僅需檢視報表者建議指派 reader 類角色，以符合最小權限原則。
  • 網路：允許 *.cloud.microsoft 與 Microsoft Copilot 端點；確認 proxy、防火牆、Conditional Access、tenant restrictions 及應用程式控制政策未封鎖 Copilot app（copilot.cloud.microsoft）。
  • Windows 用戶端：已部署統一版 Microsoft Copilot app，並將更新通道設定為 Beta（詳見 STEP 5）。

3啟用步驟

建議依下列順序設定：先完成 spending policy 與額度設定，再開放 Frontier，以確保 Credits 依規劃分配。

  1. 設定 spending policy（如圖 2）

    Microsoft 365 admin center › Copilot › Cost management › Spending policies › 選取政策 › Edit copilot agents and services

    1. 關閉「Allow new Agents and services as they become available」，避免後續推出的服務自動納入政策並消耗 Credits。
    2. 於 Microsoft Copilot 項下勾選 Code（COPILOT LICENSE REQUIRED）。
    3. 勾選 Copilot Managed Runtime，以支援 Code 所建置應用程式的執行。
    4. Cowork、Advanced work in OneDrive / SharePoint、Work IQ API 等其他服務，請依預算規劃決定是否勾選。
    5. 選取 Save changes。政策變更需一段時間生效，建議稍後以測試帳號驗證。
    預設值說明新建 spending policy 時，「Allow new Agents and services as they become available」預設為開啟，所有服務（含 Code 與 Cowork）均會勾選並共用同一額度（如圖 3）。關閉此開關僅影響後續推出的新服務，已勾選的服務須手動取消。

  2. 設定適用對象、上限與警示

    • Access scope：指定適用的使用者或群組，建議先以試行群組為範圍。
    • Limits：設定政策每月上限與每位使用者每月上限（官方目前建議每人每月至少 2,000 credits，實際以介面提示為準）。
    • Alerts：設定用量門檻通知（額度或百分比）；已設定每人上限時，亦可啟用使用者端提醒。

  3. 開放 Frontier 予試行群組

    Microsoft 365 admin center › Copilot › Settings › View all › Copilot Frontier

    指定可存取 Frontier 功能的使用者（適用 Microsoft Copilot app 及 Word / Excel / PowerPoint 網頁版）。建議以 Entra 安全性群組管理，例如 SG-Copilot-Code-Pilot。

  4. 設定 Copilot Code 功能控制項

    Microsoft 365 admin center › Copilot › Settings，於搜尋欄輸入「code」，即可看到 4 項 Copilot Code 設定（圖 5）：Organization data in local Code sessions、GitHub account connection in Code、Code execution location、Automatic approval in Code。各項設定說明與建議值詳見第 4 節（圖 6–9）。

    亦可於 Copilot › Code 管理頁的 Code readiness › Recommended actions 檢視各項設定的完成狀態（圖 4）。

    停止使用 Copilot Code
    1. 於 Copilot › Cost management › Spending policies 取消勾選 Code：使用者將無法使用 Code，畫面顯示「要求存取權」（圖 1）。
    2. 如需隱藏 Code 分頁，可於 Copilot › Code › Code readiness 調整 Make Code discoverable（圖 4）。
      注意：關閉此設定會一併關閉其他相關服務，請於變更前評估影響範圍。
    3. 亦可透過 Copilot Frontier 的使用者範圍控管；此方式會同時影響其他 Frontier 功能。

    政策變更需一段時間生效，請以測試帳號確認。設定名稱以租戶實際畫面為準。

  5. 部署 Windows 用戶端（Frontier 期間）

    • 將租戶加入統一版 Copilot app 推出範圍：部署 unified Microsoft Copilot application。
    • 將 Windows 更新目標通道設定為 Beta（參見 Microsoft Copilot update policies for Windows）。若不適用群組原則，可設定下列登錄機碼並透過 Intune / MDM 派送：
      HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\EdgeUpdate\TargetChannel{C50565E9-CCCF-44B4-BA15-5AC5C6569197} = beta
    • 使用者首次於 Windows 開啟 Code 時，系統會下載一次必要元件。如需縮短首次開啟時間，可啟用「Pre-install Copilot Code components」（若後台提供此設定）。

  6. 試行、監控與擴大

    • 透過 Copilot › Code › Usage 檢視 Copilot Code 的採用與使用狀況。
    • 透過 Cost management › Overview / Consumption，依使用者、群組、服務或 agent 檢視用量，掌握主要成本來源。
    • 處理存取申請：使用者可申請使用 Code 或提高額度上限，申請會顯示於 Copilot › Code 的「People are waiting for access to Code」，管理者可透過 Manage pending policies 審核（圖 4）。
    • 如需自動化報表，可使用 Microsoft 365 Copilot Cost Management API（Microsoft Graph）。
    • 使用者可自行檢視用量與額度，有助建立成本意識。

4管理控制項（Admin controls）

以下設定於組織層級套用。「官方預設」依據 Microsoft Learn；「建議」欄為導入建議，請依組織資安政策調整。

管理介面

Microsoft 365 admin center 提供兩個 Copilot Code 管理入口：

  • Copilot › Code：Copilot Code 專屬管理頁，包含 Overview 與 Usage 分頁。可檢視 Code 涵蓋率、使用者存取申請、計費設定狀態，以及 Code readiness 中各項建議設定的完成狀態（Allow Code to use Organizational data、Add allowed domains for GitHub、Enable GitHub account connection、Enable Code on local devices、Make Code discoverable、Automatic approval in Code）。
  • Copilot › Settings：搜尋「code」即可設定 4 項 Copilot Code 控制項，各項均可指定適用的使用者或群組。

各項設定說明

Organization data in local Code sessions

允許本機執行的 Copilot Code 使用 Work IQ 與 plugin 提供的資料（含 Microsoft Graph 中的 Teams 對話、文件、郵件與行事曆）產生程式碼與其他產出。此設定僅適用於本機執行。

介面提示納入本機產出的 Work IQ 資料，不會自動繼承 Microsoft 365 DLP、敏感度標籤、保留、eDiscovery 或訴訟保留（legal hold）保護。

GitHub account connection in Code

允許使用者將 GitHub 帳號連結至 Copilot Code，以存取 GitHub repository。可設定為全部使用者、不開放或僅開放特定群組。

Code execution location

設定 agent session 的執行位置：使用者裝置與雲端，或僅限雲端。選擇 Cloud only 時，將封鎖使用者裝置上的本機執行。

介面提示（預覽期間限制）啟用本機模式時，Copilot Code 可能於未使用沙箱的情況下在使用者裝置上無人值守執行，並可能影響專案以外的檔案；Purview DLP 與產出內容標籤暫不支援，本機儲存的資料不在 Microsoft 365 保留、訴訟保留及 eDiscovery 範圍內。儲存設定即表示管理者已知悉此提示。

Automatic approval in Code

控制 Copilot Code 是否可依核准層級自動核准動作，而非由使用者手動核准所有動作。此設定僅適用於 Code 內執行的動作。

合規與稽核

身分

以 Microsoft Entra 工作帳號登入；GitHub 帳號為選用。

治理

相容於既有 Microsoft 365 企業治理機制；程式碼執行可設定隔離與管控等級。

使用者同意

本機專案於存取專案資料夾以外位置、建立網路連線或執行終端命令前，均會先徵求使用者同意。

5費用控管：Copilot Credits

使用費用預設設定下，Code 與 Cowork 共用同一 Credits 額度與上限，建議事先規劃額度分配（參見 STEP 1）。

控管機制

  • Spending policy：控制各使用者／群組可使用的服務
  • 政策每月上限與每人每月上限（hard cap）
  • 用量門檻警示（管理者與使用者）
  • Model profiles 與 billing method 指派
  • Consumption 分析：依使用者、群組、服務或 agent 檢視

規劃建議

  • 分別設定政策：Cowork 與 Code 分別建立政策，或至少分別設定每人上限。
  • 分階段導入：試行 4–6 週，依實際用量估算全面推出所需預算。
  • 納入執行成本：發佈至 Copilot Managed Runtime 的 app 於使用時亦會消耗 Credits，應一併納入預算。

6GitHub 連線

無需 GitHub 授權Copilot Code 的核心功能不需要 GitHub 帳號、GitHub Enterprise 或 GitHub Copilot 授權。設定中與 GitHub 網域相關的選項，僅於開放 GitHub 連線時需要設定。

連線後可使用的功能

  • 以既有 repository 建立專案，並查詢 repository 內容
  • 建立 branch / commit、建立 draft pull request、push 變更
  • 為 Code 專案建立新的 repository（限 local 專案）
  • 於 My Work 檢視 issue 與 pull request

管理控制

  • GitHub account connection in Code：預設 No users
  • Add allowed domains for GitHub：Both / GitHub.com only / GitHub Enterprise only / None
  • 可限制僅能連線與租戶關聯的 GitHub 帳號
  • 開放後，GitHub 端服務可能另行計費

7導入策略

A. 受控試行（建議）

適用情境：多數金融業與大型企業。

做法：僅開放試行群組；Code execution location 設為 Cloud only，Automatic approval in Code 與 GitHub account connection in Code 設為 No users，並搭配專用政策與每人上限。

預期成果：4–6 週後取得用量基準與 3–5 個實際應用案例。

B. 全面開放

適用情境：Credits 預算充足、資料治理成熟的組織。

做法：評估啟用 Pre-install Copilot Code components，依部門設定政策與上限，並定期檢視 Consumption。

前提：已完成權限盤點、敏感度標籤與 DLP 設定。

8常見問題（FAQ）

Q1. 使用者已具備授權，但無法使用 Code，應如何排查？

顯示「要求存取權」：通常為 spending policy 未勾選 Code，或政策變更尚未生效（參見圖 1、圖 2）。
顯示「Code 無法完成此要求」：請確認 spending policy 已同時勾選 Copilot Managed Runtime（參見圖 2）。
未顯示 Code 分頁：請依序確認 ① 使用者是否位於 Frontier 允許範圍；② Copilot › Code › Code readiness 中 Make Code discoverable 是否已完成；③ 使用者是否已納入含 Code 的 spending policy；④ Windows 是否已部署統一版 Copilot app 並設定為 Beta 通道；⑤ 功能採分批推出，可重新整理或稍後再試。

Q2. Code 與 Cowork 是否共用 Credits？

是。兩者均以 Copilot Credits 計費；位於同一 spending policy 時共用同一上限。建議分別設定政策或每人上限。

Q3. 使用者申請使用 Code 或提高額度時，管理者如何處理？

申請會顯示於 Copilot › Code 管理頁的「People are waiting for access to Code」，管理者可選取 Manage pending policies 審核，並將使用者加入對應的 spending policy 或調整額度上限（參見圖 4）。

Q4. 是否需要 GitHub Enterprise 或 GitHub Copilot 授權？

不需要。GitHub 連線為選用功能，預設為關閉。

Q5. 使用者建置的 app 是否會自動分享至全組織？

不會。雲端 app 須由使用者另行發佈至 Copilot Managed Runtime 後才能分享；靜態 app 可透過僅限組織內的連結分享（限雲端）。本機專案保留於使用者裝置。

Q6. 哪些角色可設定費用政策？

Global Administrator 與 Billing Administrator 可建立政策並設定 billing method；AI Administrator 與 License Administrator 可編輯政策、上限與警示，但無法建立政策；reader 類角色僅可檢視報表。
