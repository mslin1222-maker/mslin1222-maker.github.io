      STEP 07 · GOVERNANCE & TRUST

      先講清楚邊界，信任才建得起來

      對做系統、做數據的人來說，「它能讀到什麼、不能讀到什麼」比功能清單更重要。這一段把 Copilot 的資料邊界、權限模型、模型選擇與需要確認的動作一次講清楚。

      🛡️

      你的資料就是你的

      提示與回應不會用於訓練基礎模型；資料在靜態與傳輸中皆加密；你可以控制資料位置。受 Microsoft 客戶版權承諾保護。

      🔑

      沿用既有權限

      Copilot 只看得到你本人在 Microsoft 365 裡本來就看得到的東西（Email、會議、Teams、SharePoint / OneDrive）。沒有權限的 SRS、合約，它也看不到。

      🧠

      Multi-model：適合工作的模型

      Copilot 依任務自動選用 OpenAI 與 Anthropic 模型（快速回應 / 深度思考）；租戶管理員可套用控制措施。Researcher 的 Critique / Council 模式就是多模型互審。

      🔒

      敏感動作先問你

      • 寄出郵件、發 Teams 訊息
      • 建立 / 修改行事曆
      • 把待辦指派給他人（Planner）
      • 寫入 SharePoint 共用資料夾
      • 分享 Agent 給群組
      📊

      每次回覆附「信心評估」

      在 Copilot 個人化設定加入：信心分數 / 判斷依據 / 主要來源 / 建議動作；低於 60 分必須建議驗證步驟。讓「AI 說的」變成「可核對的」。

      🧪

      第三方外掛需經評估

      Agent 商店與 Copilot Studio 可接第三方 SaaS 連接器；涉及外部資料傳輸者，建議先經資安與委外評估，再開放給團隊。

      誠實的邊界：Copilot 讀得到什麼？讀不到什麼？

      這通常是情報系統部第一個問題。答案分兩邊：

      ✅ 直接可用（Microsoft Graph 內）
      • Outlook 郵件、行事曆
      • Teams 聊天、頻道、會議 transcript 與 Recap
      • SharePoint / OneDrive 的 Word、Excel、PPT、PDF
      • Planner、Loop、Copilot Pages
      • 你上傳到對話中的檔案
      ⚠ 需要一段路（POS / CDP / 資料倉）
      • POS、AI 訂貨、CDP（Databricks）等系統資料：先匯出成 Excel / CSV 到 SharePoint，Analyst 就能分析
      • 要即時查詢：透過 Graph Connector 或 Copilot Studio 接 API，成為 Agent 的知識來源
      • 要把 Copilot 嵌進門市或內部系統：Copilot Studio / Agent SDK
      • 本站所有示範情境都以「已匯出到 M365 的檔案」為前提
      使用者在 M365 應用程式輸入提示 → Copilot 以「接地（grounding）」前置處理，透過 Microsoft Graph 取得使用者有權限的資料 → 送到 LLM 產生回應 → 回傳給應用程式。資料在傳輸中加密，全程在 Microsoft 365 服務邊界內。
      Word / Excel / PowerPoint Copilot 與 Office Agents、Cowork 的產出就是原生 Office 檔：Excel 圖表是可改範圍與樣式的物件，PPT 是可拖曳的文字框與圖表，Word 是可追蹤修訂的文件。本站每個時刻卡右下角的檔案 chip，就是這個意思。
      這不是假設：uniopen 團隊的內部問卷就有七成以上同仁提到這個風險。本站的設計回應是三個習慣——(1) 每個結論附來源，(2) 推測與資料支持分開列，(3) 信心分數低於 60 就去驗證。善用工具、理解原理，不讓工具取代思考。
      「數據不像掃地機器人一樣，放著就能幫你做事，在企業內取得更多即時數據，反而要做更多事。」— 統一超商 AI 數位群協理 張家華，《經理人》2021。Copilot 的價值不在取代這些「更多事」，而是讓做這些事的人，把時間留給判斷。
